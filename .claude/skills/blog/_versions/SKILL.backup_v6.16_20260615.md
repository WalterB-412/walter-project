# 네이버 블로그 포스팅 프롬프트 v6.15
SEO · AEO · GEO · 홈판 · 서치피드 · AuthGR 통합형

## 사용 방법

1. 사용자가 입력한 [주제]로 작업한다.
2. STEP 0부터 순서대로 진행한다.
3. 단계 순서 변경·생략·병합 금지.
4. 글은 마크다운 파일로 작성 금지.
5. 최종 출력: 네이버 블로그 바로 붙여넣기 형태.
6. STEP 4 완료 후 STEP 5(카드뉴스)를 자동으로 이어서 진행한다. 별도 명령 없이 실행.
7. STEP 5 완료 후 STEP 6(숏폼 영상)을 자동으로 이어서 진행한다. 별도 명령 없이 실행.

## 시작 전 필수 판별

### ① 질의 유형 (최우선)
- 정보형(정의·방법·조건) → AEO·GEO 풀가동
- 비정보형(상업·비교·거래) → AEO·GEO 생략, SEO 집중

### ② 유입 목적
검색(SEO) / 홈판(클릭) / AI브리핑(AEO·GEO) / 서치피드

### ③ 핵심 독자
직장인 / 자영업자 / 프리랜서 / 사회초년생

### ④ AEO 인용 후보 문장 3개 사전 설계
- 형식: "[용어]는 [정의]다." (20자 이내, 정의문만 허용)
- 소제목 결론 문장과 동일 문장 사용 금지
- 독립 단락 배치 (앞뒤 줄바꿈 + 문장 직후 엔터)
- 정답 박스 단정형 결론과 동일 형식 유지

## 형식 앵커

각 섹션 작성 시 아래 형식을 기준으로 삼는다.

| 섹션 | 형식 |
|---|---|
| 정답 박스 | [단정형 결론 20자↓] · [수치 포함 결론] · [조건형 결론] + ▶ 실행 3단계 (동사 시작, 기한 포함) |
| 들어가며 | [독자 상황] → [문제] → [결과 약속] + 말미: "이 글을 정리한 이유는 ~이다." |
| 중간 요약 | ① 소제목명: 결론 1줄 압축 (소제목 원문 그대로 복사 금지) |
| FAQ | Q. [본문 미포함 질문] / A. 단정형 2~3줄 × 5개 |
| 요약 표 | 항목 \| 수치·조건·기한 (문장형 설명 금지) |

※ 같은 문장 2곳 이상 → 즉시 삭제
※ 같은 수치 3곳 이상 → 최초 1곳만 유지

## STEP 0 — 웹검색 사전 수집

① 최신 법령·고시·정책 변경 내용
② 핵심 수치 (세율·한도·기간·금액) + 공식 출처 (국세청·기재부·법제처 등)
③ 시행 시기 및 적용 연도
④ 네이버 자동완성 키워드 5개
⑤ 연관검색어 5개
⑥ 검색 의도: 정보형 / 실행형 / 비교형 / 경고형 / 해석형 중 선택
⑦ 발행 주기 확인: 최근 발행일, 주 2~3회 간격 권장 / 시리즈 연결 가능 여부 → 가능하면 STEP 3.5 활용

⑧ 실제 후기 서칭 + 체험 소재 수집
검색 쿼리: "[주제] 후기/실수/안됨/막힘/오류/해결" (네이버 카페·블로그 우선)

수집 목표:
- 막힘 사례: 공식 안내에 없는 오류·예외 → "[상황] → [발생 문제]"
- 반전 사례: 기대와 달랐던 결과 → "[예상] vs [실제]"
- 수치 사례: 실제 절약·손해 금액 → "[조건] → [금액·기간]"

※ 익명 처리 / 출처: "네이버 카페 후기 참고" 수준으로만 표기
※ 검색 결과 없으면 "(예상 시나리오)" 표기 후 진행

## STEP 1 — 포스팅 본문 작성

### 문체·형식
- 존댓말 금지 / ~한다·~이다 형식
- 본문 3,000자 이내 / 억지 분량 늘리기 금지
- 수치·날짜·출처 병기: 예) "5월 31일까지 (국세청 기준)"
- 말미 면책 고지 필수

### 줄바꿈 규칙 — 전 구간 예외 없음
- 1줄 = 공백 포함 23자 이내, 초과 시 즉시 엔터
- 1문단 = 2~4문장 / 소제목: ① ② ③ 번호 삽입

### GEO 파싱 신호 — 정보형 질의만 적용
① 소제목 직후 첫 문장 → 결론형 필수: "~는 ~이다." / "~하면 ~된다."
② 소제목 1개 이상 → 질문형 필수: "~는 어떻게 하나?" / "~은 무엇인가?"
③ 숫자·조건·기한 → 문단 첫 줄 배치 (중간 삽입 금지)
④ 각 소제목 → 타 소제목 참조 없이 단독 완결 구조

### 신뢰 장치 — 필수 3종
- 조건 명시: "~의 경우에만 해당한다."
- 주의사항: "~라고 오해하기 쉽지만, 실제로는 ~이다."
- 과장 제거: "무조건" → "가능성이 높다" / "누구나" → "대부분"

### 표 vs 텍스트
- 표 사용: 항목 비교 / 공제율·세율·한도 / A vs B 비교 / 조건별 정리
- 줄글 사용: 개념·흐름 / 주의사항·예외·팁 / 행동 가이드 / 마무리 체크리스트

### 소제목별 단락 구조 — 5단계 의무

**1단계.** **결론 (3줄 이내, 굵게)** ← GEO: 첫 문장 반드시 결론형
**2단계.** 이유·근거 (출처 병기)
**3단계.** 막힘·실수담 ← STEP 0 ⑧ 수집 소재 우선 활용
  - 형식: "~라고 나와있지만, 실제로 해보니 ~이었다."
  - 소재 없으면 커뮤니티 사례 또는 "(예상 시나리오)" 대체
**4단계.** 수치 시뮬레이션 또는 Before/After 비교
**5단계.** ※ 주의사항·예외

사례 우선순위: ① 체험(직접·지인·커뮤니티) ② 수치 시뮬 ③ 통계 인용 ④ B/A 비교 ⑤ 가상 인물 (최후 수단, 전체 최대 2회)

**소제목 구조 예시:**

> **① 매입세액이란 무엇인가?**
>
> **매입세액은 사업 과정에서 지출한 부가세다.**
> 세법 제38조 기준,
> 공제 가능 항목만 환급 대상이다.
> 홈택스 안내엔 '자동 조회'라고 나오지만,
> 카드 매출 누락분이 빠지는 경우가 잦다.
> (네이버 카페 후기 참고)
> 카드 지출 500만원 기준 → 매입세액 45만5천원 공제 가능.
> ※ 간이영수증 지출은 공제 대상에서 제외된다.

### 포스팅 필수 항목 — 순서 준수

**1. 제목 3안**
- 클릭형: "[직접 ~했더니] + [예상 밖 결과]"
- 경고형: "[기한·조건] + [손해 수치] + [내 행동]"
- 검색형: "[연도] + [핵심 키워드] + [정량 결과]"
- ※ 클릭형·경고형 중 1개 이상: "직접/해보니/내가" 포함 필수

**2. 메타설명:** 핵심결론 + 수치 + 독자혜택, 100~150자

**2-1. 카테고리 태그:** [대분류] [중분류] [세부주제] (해시태그 혼용 금지)

**3. 용어 해설 표:** 5~7개 / "[용어]는 [정의]다." 형식 / 각 정의문 독립 단락

**4. 목차:** [이 글에서 다루는 내용] ✔ 형식

**5. 정답 박스:** 형식 앵커 참고

**6. 들어가며:** 형식 앵커 참고

**7. 소제목별 본문:** 5단계 구조 + 중간 질문 1개 + 강조 문장 2개

**7-1. 중간 저장 유도** (소제목 ②~③ 사이, 1회만) — 실제 제공 가능한 것 1개 선택:
- "이 글 마지막에 조건별 비교 표를 정리해뒀다."
- "마지막에 잘못 신청한 3가지 사례와 정정법을 정리했다."
- "마지막 섹션에 신청 전 5가지 체크리스트를 만들었다."

**8. 중간 요약:** 형식 앵커 참고

**9. FAQ 5개:** 형식 앵커 참고 (본문에서 다룬 질문 재사용 금지)

**10. 최종 요약 표:** 형식 앵커 참고

**11. 마무리**
- 독자 질문 유도 (마무리 직전, 1회): "이 과정에서 [구체적 경험] 어떻게 하셨나요?"
  - ※ "도움이 되셨나요?" 형식 금지 / 구체적 경험 질문이어야 한다
- CTA 2단: 1단-저장·이웃추가 / 2단-심화 콘텐츠 유도

**12. 면책 고지:** "※ 본 포스팅은 [년월] 기준. 출처: [공식URL]"

### SEO
- 제목: 핵심 키워드 + 연도 필수 (예: "2026년 종합소득세")
- 롱테일 키워드 1개 이상 / 본문 전체 핵심 키워드 3~5회

### GEO·AEO — 정보형만
- 첫 200자 안에 핵심 답변 배치
- AEO 문장 3개: 독립 단락 + 앞뒤 줄바꿈 + 정답 박스 결론과 동일 형식

### 서치피드
카테고리 태그 → 저장 유도 → 썸네일 5~8자

### AuthGR
저자관점(들어가며) + 체험서술(소제목 3단계) + 용어해설 + URL + 주 2~3회 발행

## STEP 2 — 보완 검증 + 인용 스니펫

검증 대상: STEP 1 작성 중 새로 생긴 불명확 수치만

- 있으면: 웹검색 → `| 항목 | 수정 전 | 수정 후 | 근거 |` 표 작성
- 없으면: "추가 검증 없음" 명시 후 진행 (전수 재검증 금지)

검증 우선순위: 세율·한도 → 기한 → 제도명 → 조건

**인용 스니펫 목록화 (정보형만)** — 3~5개

| # | 스니펫 문장 | 위치 | 유형 |
|---|---|---|---|
| 1 | 예시 문장 | 소제목① | 정의형 |

유형: 정의형("~는 ~이다.") / 수치형 / 실행형 / 경고형

※ 본문 포함 문장만 / 목록화 후 독립 단락 배치 재확인

## STEP 3 — 이미지 프롬프트

들어가며·소제목마다 1개씩 작성.
스타일 순환 (연속 동일 스타일 금지):
① 실사 사진 ② 플랫 인포그래픽 ③ 캐릭터·일러스트
④ 타이포그래픽 ⑤ 플랫레이 실사 ⑥ 경고 인포그래픽 ⑦ 데이터 시각화

비율: 16:9 또는 9:16 랜덤 (동일 비율 3회 연속 금지)

**트랙 A — 상황실사형 (① ⑤ 해당)**

필수 소품: 영수증·통장·앱화면·서류·계산기 중 1개 이상
프롬프트 필수 포함:
```
shot on iPhone 15, natural candid photography, realistic photo,
authentic texture, slightly messy desk, natural window light,
1/125s shutter, no AI artifacts, documentary style
```
인물: 한국인·나이대·상황 묘사 / 얼굴 미노출

**트랙 B — 숫자강조형**

핵심 수치 1개 중앙 배치 (이미지 높이의 25% 이상 크기)
프롬프트 필수 포함:
```
flat design infographic, bold number [수치] centered,
high contrast background, clean minimal layout,
Korean text overlay, no AI artifacts
```
Text overlay: 수치 + 단위 + 기준연도 (한글만, 영문 혼용 금지)

※ 트랙 A↔B 교대 배치 권장 / 동일 트랙 3회 연속 금지
썸네일: 915×507px / 한글 강조 문구 5~8자 / 영문 금지

## STEP 3.5 — 시리즈 연결 (생략 금지)

① 이전 글 연결 (해당 시): 마무리 직전 → "▶ [포스팅 제목]"
② 다음 글 예고 (항상): 마무리 직후 → "다음 글에서는 ~을 정리할 예정이다."
③ 시리즈 태그: 카테고리 태그에 추가 → [시리즈명] [주제편]

※ 이전·예고 각 1회씩, 과도한 홍보 문구 금지

### 6-1. 작업 폴더 / 산출물

### 6-2. 영상 구성 (11~13씬 / 약 50초, 1씬 = 1문장)

| 구간 | 씬 수 | 비고 |
|---|---|---|
| 훅 | 2 | 첫 1~2초가 시청 유지 결정 — 후킹 공식 1개 적용 |
| 미끼 | 1 | "끝까지 보면 얻는 것" 예고 |
| 핵심 포인트 | 6~8 | 본문 핵심을 씬당 1문장 |
| 클라이맥스 | 1 | 가장 중요한 결론·수치 |
| CTA | 1 | 저장·팔로우·프로필 링크 유도 |

### 6-3. 나레이션 작성 원칙 ★가장 중요 (이거 안 지키면 단조로운 영상)

**핵심: 화면(이미지)은 참고자료, 나레이션(`text`)이 주인공이다.**
`text`를 화면 `title`을 그대로 옮긴 설명문으로 쓰면 안 된다. 이미지의 의미만 해치지 않으면
**호기심을 유발하는 자유로운 구어체 대본**으로 새로 쓴다.

작성 규칙:
1. **전체가 하나의 이야기** — 씬을 독립된 정보 나열로 쓰지 말 것. 앞 씬이 다음 씬을
   궁금하게 만드는 흐름(클리프행어): "근데 여기서 함정이…", "문제는 지금부터입니다"
2. **첫 1~2씬에 강한 호기심 후킹** (아래 패턴 중 1개):
   - 정보격차: "이거 모르고 있으면 진짜 큰일 납니다"
   - 손실 회피: "이 돈, 신청 안 하면 그냥 날아갑니다"
   - 사례·스토리: "얼마 전 한 사장님이 이거 몰라서 3천만원 놓쳤습니다"
   - 반전/궁금증: "은행이 거절한 사람만 받을 수 있다는데, 왜일까요?"
   - 질문 던지기: "내가 받을 수 있는지, 30초면 알 수 있습니다"
3. **구어체·짧은 문장·말맛** — 문어체 금지("~합니다만" X). 실제 말하듯이.
4. **어미를 섞어라 ★중요** — 모든 문장을 "~입니다/~습니다"로 끝내면 기계처럼 들린다.
   - 단정: ~입니다 / ~습니다 / ~죠
   - 설명·공감: ~거든요 / ~잖아요 / ~더라고요
   - 부드러움: ~했어요 / ~네요 / ~예요·이에요
   - 질문: ~일까요? / ~아세요?
   - **같은 어미 3연속 금지**, 특히 "~입니다" 반복 금지. 니다체와 요체를 자연스럽게 섞을 것
5. **핵심만** — 숏폼은 한 영상에 메시지 1개. 곁가지 정보는 버리고 후킹→핵심→행동으로.
6. **마지막 CTA**는 놓침 압박 + 저장 유도: "마감 지나면 또 1년 기다려요", "지금 안 챙기면 다음에 못 찾아요" (※ "프로필 링크 확인" 같은 안내성 문구는 쓰지 말 것)

> `title`(화면)과 `text`(나레이션)는 **서로 달라도 된다**. title은 짧은 시각 키워드,
> text는 귀로 듣는 이야기. 예: title "신용 839점 이하" / text "이거 모르면 3천만원 날립니다"

### 6-4. 씬 타입 결정 트리 (위에서부터 first-match — 모호하면 순서가 우선)

```
1. 순서 있는 절차·단계가 핵심?        → list
2. 두 항목의 '대비/전환'이 메시지?     → compare  (before→after, A보다 B)
3. 단일 수치 하나를 각인시키는 게 핵심? → stat
4. 그 외 일반 설명                    → scene
훅 씬은 hook, 마지막 씬은 cta 고정
```

- stat vs compare 타이브레이커: 결론이 **한 값**이면 stat, **둘의 격차**면 compare
- 가드레일: 영상당 stat·compare 각 **최대 1개**. compare는 좌/우 양쪽을 의미 있게 채울 수 있을 때만(아니면 stat/scene)

### 6-5. 필드 규칙

- `title` = **화면 비주얼용** 짧은 키워드/강조 (줄바꿈 `\n`). 나레이션을 그대로 넣지 말 것
- `text` = **나레이션 = 음성(TTS) + 자막 공용 단일 소스**. 6-3 원칙대로 호기심 후킹 대본으로 작성
- 화면엔 본문 텍스트가 없다(자막이 나레이션 담당) → title은 한눈에 읽히는 짧은 문구로
- 글자수: 훅/CTA `text` 20자 이내 / 내용 씬 30~40자 이내 (자막 2줄 넘기지 않게)

### 6-6. scenes.json 스키마

```json
{
  "brand": "Walter 경제",
  "category": "(포스팅 핵심 키워드)",
  "total": 6,
  "scenes": [
    {"type":"hook","tag":"⚠ 지금 확인","title":"신용 839점 이하\n사장님 주목","text":"이거 모르면 3천만원 그냥 날아가요"},
    {"type":"scene","tag":"왜 지금","title":"1년에 딱\n한 번","text":"이 자금, 곧 닫히고 1년은 더 기다려야 하거든요"},
    {"type":"stat","tag":"금리","title":"올해 금리","stat_value":"5.04%","stat_caption":"역대급 저금리","text":"카드론의 3분의 1, 연 5%면 끝납니다"},
    {"type":"compare","tag":"전 / 후","title":"뭐가 다르냐면","compare_left":{"label":"신청 전","value":"고금리 카드론"},"compare_right":{"label":"신청 후","value":"연 5% 정책자금"},"text":"고금리 돌려막기, 여기서 한 번에 끝나죠"},
    {"type":"scene","tag":"주의","title":"근데\n함정이","text":"서류 하나만 빠져도 바로 탈락이에요"},
    {"type":"cta","tag":"핵심 요약","title":"지금\n저장하세요","text":"지금 안 챙기면 또 1년 기다려요","cta_button":"저장하고 팔로우","summary":[{"label":"신청 기간","value":"6월 15~16일","color":"blue"},{"label":"한도","value":"최대 3,000만원","color":""}]}
  ]
}
```

- 위는 **축약 예시(6씬)**. 실제는 11~13씬으로 핵심 씬을 더 넣는다
- `total`은 **실제 scenes 개수와 정확히 일치**시킨다 (무결성 검사가 total로 누락을 잡음)
- 타입별 필수 필드: stat=`stat_value` / compare=`compare_left.value`·`compare_right.value` / list=`list_items[]` / cta=`summary[].label`·`value`
- `color`는 `blue`/`red`/`""`만 사용

### 6-7. 실행 (Bash 자동)

scenes.json 저장 후 아래를 순서대로 실행한다. **이전 실행 잔여물 정리 → 검증·렌더 → 캡처 → TTS → 영상**:

```bash
cd "/Users/kakao/Documents/2. 개인/Walter Project/02_자동화/숏폼_자동화"
rm -f output/scenes/*.html output/scenes/*.png output/tts/*.mp3   # 잔여물 정리(씬 혼입 방지)
python3 scene_render_v1.3.py scenes.json                          # 검증+HTML (실패 시 여기서 중단)
node capture_v1.2.mjs output/scenes                               # HTML→PNG (로컬 puppeteer, 누락 시 종료)
python3 tts_run_v1.4.py scenes.json                               # ⚠️ Google Chirp3-HD(쉼표 쉼 처리) → Edge → gTTS 폴백
BGM=""; [ -f assets/bgm.mp3 ] && BGM="--bgm assets/bgm.mp3"        # assets/bgm.mp3 있으면 BGM 자동 사용

```

- `tts_run_v1.4.py` ⚠️ 1차 엔진은 Google Chirp3-HD(유료, 영상당 약 1센트). 쉼표에서 자동으로 쉼(`--pause` 조정). 보이스 교체: `--voice ko-KR-Chirp3-HD-<이름>` / 속도: `--rate 1.30`. 키 없거나 실패하면 무료 Edge(Hyunsu)→gTTS로 자동 폴백
- **BGM**: 저작권 free 음원(YouTube 오디오 보관함·Pixabay 등)을 `assets/bgm.mp3`로 두면 자동으로 깔림(없으면 BGM 없이 진행)
- `scene_render_v1.3.py`가 JSON 필수 필드를 검증한다 — 실패하면 멈추므로 누락 항목을 고쳐 다시 실행
- `video_build`는 `--scenes-json`으로 기대 씬 수를 검증해 **씬 누락 영상 생성을 차단**한다
