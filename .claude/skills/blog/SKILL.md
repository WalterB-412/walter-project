# 네이버 블로그 포스팅 프롬프트 v6.17
SEO · AEO · GEO · 홈판 · 서치피드 · AuthGR 통합형

## 사용 방법

1. 사용자가 입력한 [주제]로 작업한다.
2. STEP 0부터 순서대로 진행한다.
3. 단계 순서 변경·생략·병합 금지.
4. 글은 마크다운 파일로 작성 금지.
5. 최종 출력: 네이버 블로그 바로 붙여넣기 형태.
6. STEP 4 완료 후 STEP 5(카드뉴스)를 자동으로 이어서 진행한다. 별도 명령 없이 실행.
7. STEP 5 완료 후 STEP 6(숏폼 영상)을 자동으로 이어서 진행한다. 별도 명령 없이 실행.

## 시작 전 필수 판별

### ① 질의 유형 (최우선)
- 정보형(정의·방법·조건) → AEO·GEO 풀가동
- 비정보형(상업·비교·거래) → AEO·GEO 생략, SEO 집중

### ② 유입 목적
검색(SEO) / 홈판(클릭) / AI브리핑(AEO·GEO) / 서치피드

### ③ 핵심 독자
직장인 / 자영업자 / 프리랜서 / 사회초년생

### ④ AEO 인용 후보 문장 3개 사전 설계
- 형식: "[용어]는 [정의]다." (20자 이내, 정의문만 허용)
- 소제목 결론 문장과 동일 문장 사용 금지
- 독립 단락 배치 (앞뒤 줄바꿈 + 문장 직후 엔터)
- 정답 박스 단정형 결론과 동일 형식 유지

## 형식 앵커

각 섹션 작성 시 아래 형식을 기준으로 삼는다.

| 섹션 | 형식 |
|---|---|
| 정답 박스 | [단정형 결론 20자↓] · [수치 포함 결론] · [조건형 결론] + ▶ 실행 3단계 (동사 시작, 기한 포함) |
| 들어가며 | [독자 상황] → [문제] → [결과 약속] + 말미: "이 글을 정리한 이유는 ~이다." |
| 중간 요약 | ① 소제목명: 결론 1줄 압축 (소제목 원문 그대로 복사 금지) |
| FAQ | Q. [본문 미포함 질문] / A. 단정형 2~3줄 × 5개 |
| 요약 표 | 항목 \| 수치·조건·기한 (문장형 설명 금지) |

※ 같은 문장 2곳 이상 → 즉시 삭제
※ 같은 수치 3곳 이상 → 최초 1곳만 유지

## STEP 0 — 웹검색 사전 수집

① 최신 법령·고시·정책 변경 내용
② 핵심 수치 (세율·한도·기간·금액) + 공식 출처 (국세청·기재부·법제처 등)
③ 시행 시기 및 적용 연도
④ 네이버 자동완성 키워드 5개
⑤ 연관검색어 5개
⑥ 검색 의도: 정보형 / 실행형 / 비교형 / 경고형 / 해석형 중 선택
⑦ 발행 주기 확인: 최근 발행일, 주 2~3회 간격 권장 / 시리즈 연결 가능 여부 → 가능하면 STEP 3.5 활용

⑧ 실제 후기 서칭 + 체험 소재 수집
검색 쿼리: "[주제] 후기/실수/안됨/막힘/오류/해결" (네이버 카페·블로그 우선)

수집 목표:
- 막힘 사례: 공식 안내에 없는 오류·예외 → "[상황] → [발생 문제]"
- 반전 사례: 기대와 달랐던 결과 → "[예상] vs [실제]"
- 수치 사례: 실제 절약·손해 금액 → "[조건] → [금액·기간]"

※ 익명 처리 / 출처: "네이버 카페 후기 참고" 수준으로만 표기
※ 검색 결과 없으면 "(예상 시나리오)" 소재로만 활용 — STEP 0.5 팩트 테이블과 별도 관리

## STEP 0.5 — 팩트 테이블 구축

STEP 0 완료 직후 실행. **STEP 1 진행 전 반드시 완료.**

### ① 검증 필요 항목 추출

STEP 0 수집 내용에서 아래 유형을 분리 추출:
- 수치: 세율·한도·금액·비율
- 날짜·기한: 시행일·신청 기간·마감일
- 법령명·조항: 조문 번호 포함
- 적용 대상 조건: 자격·요건·제외 조건

### ② 항목별 공식 출처 확인

각 항목에 대해 WebSearch 또는 WebFetch 실행:
- 검색 우선순위: `site:nts.go.kr` → `site:law.go.kr` → `site:moef.go.kr` → 기재부 보도자료
- 원문 문구 발췌 (조문 원문 또는 공식 보도자료 직접 인용)
- WebFetch 실패(JS 렌더링 차단) 시: WebSearch 상위 결과로 대체, 상태 ⚠️ 처리

### ③ 팩트 테이블 완성 (STEP 1 진행 전 필수 출력)

| 항목 | 수치·내용 | 출처 URL 또는 검색 근거 | 확인 상태 |
|---|---|---|---|
| 예) 종합소득세 최고세율 | 45% | nts.go.kr/nts/cm/... | ✅ |
| 예) 신고 기한 | 5월 31일 | nts.go.kr/nts/cm/... | ✅ |
| 예) 기본공제 한도 | 150만원 | 검색 결과 기준 | ⚠️ |
| 예) 가산세율 | 미확인 | 검색 결과 없음 | ❓ |

**확인 상태 기준:**
- ✅ 원문 확인: WebFetch 성공 + 공식 원문에서 직접 확인
- ⚠️ 검색 결과 기준: 공식 기관 언급 검색 결과 확인, 원문 미접근
- ❓ 확인 필요: 검색 결과 없음 또는 출처 불분명

### ④ 팩트 테이블 사용 규칙 — STEP 1 전 구간 적용

- ✅ 항목: 수치 그대로 사용 가능
- ⚠️ 항목: 수치 사용 가능, 문장 말미 `(검색 결과 기준)` 병기
- ❓ 항목: 수치 직접 기재 금지 → "확인 필요" 또는 서술형으로 대체
- **팩트 테이블에 없는 수치·날짜·법령명 인라인 기재 금지**
- "(예상 시나리오)" 소재: 본문 흐름에 삽입 금지 → 소제목 3단계에서 별도 인용구 형식으로만 허용

## STEP 1 — 포스팅 본문 작성

### 문체·형식
- 존댓말 금지 / ~한다·~이다 형식
- 본문 3,000자 이내 / 억지 분량 늘리기 금지
- 수치·날짜·출처 병기: 예) "5월 31일까지 (국세청 기준)"
- 말미 면책 고지 필수

### 줄바꿈 규칙 — 전 구간 예외 없음
- 1줄 = 공백 포함 23자 이내, 초과 시 즉시 엔터
- 1문단 = 2~4문장 / 소제목: ① ② ③ 번호 삽입

### GEO 파싱 신호 — 정보형 질의만 적용
① 소제목 직후 첫 문장 → 결론형 필수: "~는 ~이다." / "~하면 ~된다."
② 소제목 1개 이상 → 질문형 필수: "~는 어떻게 하나?" / "~은 무엇인가?"
③ 숫자·조건·기한 → 문단 첫 줄 배치 (중간 삽입 금지)
④ 각 소제목 → 타 소제목 참조 없이 단독 완결 구조

### 신뢰 장치 — 필수 5종
- 조건 명시: "~의 경우에만 해당한다."
- 주의사항: "~라고 오해하기 쉽지만, 실제로는 ~이다."
- 과장 제거: "무조건" → "가능성이 높다" / "누구나" → "대부분"
- 팩트 테이블 준수: STEP 0.5 팩트 테이블 ✅·⚠️ 항목만 수치 사용 / ❓ 항목은 수치 기재 불가
- 검증 상태 표기: ⚠️ 항목 수치에는 `(검색 결과 기준)` 병기 / ❓ 항목은 "확인 필요" 서술형 대체

### 표 vs 텍스트
- 표 사용: 항목 비교 / 공제율·세율·한도 / A vs B 비교 / 조건별 정리
- 줄글 사용: 개념·흐름 / 주의사항·예외·팁 / 행동 가이드 / 마무리 체크리스트

### 소제목별 단락 구조 — 5단계 의무

**1단계.** **결론 (3줄 이내, 굵게)** ← GEO: 첫 문장 반드시 결론형
**2단계.** 이유·근거 (출처 병기)
**3단계.** 막힘·실수담 ← STEP 0 ⑧ 수집 소재 우선 활용
  - 형식: "~라고 나와있지만, 실제로 해보니 ~이었다."
  - 소재 없으면 커뮤니티 사례 또는 "(예상 시나리오)" 대체
**4단계.** 수치 시뮬레이션 또는 Before/After 비교
**5단계.** ※ 주의사항·예외

사례 우선순위: ① 체험(직접·지인·커뮤니티) ② 수치 시뮬 ③ 통계 인용 ④ B/A 비교 ⑤ 가상 인물 (최후 수단, 전체 최대 2회)

**소제목 구조 예시:**

> **① 매입세액이란 무엇인가?**
>
> **매입세액은 사업 과정에서 지출한 부가세다.**
> 세법 제38조 기준,
> 공제 가능 항목만 환급 대상이다.
> 홈택스 안내엔 '자동 조회'라고 나오지만,
> 카드 매출 누락분이 빠지는 경우가 잦다.
> (네이버 카페 후기 참고)
> 카드 지출 500만원 기준 → 매입세액 45만5천원 공제 가능.
> ※ 간이영수증 지출은 공제 대상에서 제외된다.

### 포스팅 필수 항목 — 순서 준수

**1. 제목 3안**
- 클릭형: "[직접 ~했더니] + [예상 밖 결과]"
- 경고형: "[기한·조건] + [손해 수치] + [내 행동]"
- 검색형: "[연도] + [핵심 키워드] + [정량 결과]"
- ※ 클릭형·경고형 중 1개 이상: "직접/해보니/내가" 포함 필수

**2. 메타설명:** 핵심결론 + 수치 + 독자혜택, 100~150자

**2-1. 카테고리 태그:** [대분류] [중분류] [세부주제] (해시태그 혼용 금지)

**3. 용어 해설 표:** 5~7개 / "[용어]는 [정의]다." 형식 / 각 정의문 독립 단락

**4. 목차:** [이 글에서 다루는 내용] ✔ 형식

**5. 정답 박스:** 형식 앵커 참고

**6. 들어가며:** 형식 앵커 참고

**7. 소제목별 본문:** 5단계 구조 + 중간 질문 1개 + 강조 문장 2개

**7-1. 중간 저장 유도** (소제목 ②~③ 사이, 1회만) — 실제 제공 가능한 것 1개 선택:
- "이 글 마지막에 조건별 비교 표를 정리해뒀다."
- "마지막에 잘못 신청한 3가지 사례와 정정법을 정리했다."
- "마지막 섹션에 신청 전 5가지 체크리스트를 만들었다."

**8. 중간 요약:** 형식 앵커 참고

**9. FAQ 5개:** 형식 앵커 참고 (본문에서 다룬 질문 재사용 금지)

**10. 최종 요약 표:** 형식 앵커 참고

**11. 마무리**
- 독자 질문 유도 (마무리 직전, 1회): "이 과정에서 [구체적 경험] 어떻게 하셨나요?"
  - ※ "도움이 되셨나요?" 형식 금지 / 구체적 경험 질문이어야 한다
- CTA 2단: 1단-저장·이웃추가 / 2단-심화 콘텐츠 유도

**12. 면책 고지:** "※ 본 포스팅은 [년월] 기준. 출처: [공식URL]"

### SEO
- 제목: 핵심 키워드 + 연도 필수 (예: "2026년 종합소득세")
- 롱테일 키워드 1개 이상 / 본문 전체 핵심 키워드 3~5회

### GEO·AEO — 정보형만
- 첫 200자 안에 핵심 답변 배치
- AEO 문장 3개: 독립 단락 + 앞뒤 줄바꿈 + 정답 박스 결론과 동일 형식

### 서치피드
카테고리 태그 → 저장 유도 → 썸네일 5~8자

### AuthGR
저자관점(들어가며) + 체험서술(소제목 3단계) + 용어해설 + URL + 주 2~3회 발행

## STEP 2 — 팩트 대조 검증 + 인용 스니펫

### ① STEP 1 본문 전수 대조

STEP 1 본문에서 수치·날짜·법령명·조건 전체를 추출하여 팩트 테이블과 대조한다.

- 팩트 테이블 ✅ 항목: 수치 일치 여부만 확인 (재검색 불필요)
- 팩트 테이블 ⚠️ 항목: WebSearch 1회 추가 확인
- 팩트 테이블 외 수치 발견: 즉시 삭제 또는 팩트 테이블에 추가 후 재검증
- "추가 검증 없음" 선택지 없음 — 수치가 0개여도 대조 결과 표 출력 필수

### ② 대조 결과 표 출력

| 항목 | STEP 1 기재 내용 | 팩트 테이블 상태 | 조치 |
|---|---|---|---|
| 예) 세율 | 45% | ✅ 일치 | 유지 |
| 예) 신청 기한 | 6월 30일 | ⚠️ 불일치 (5월 31일) | 수정 |
| 예) 가산세율 | 10% | ❓ 테이블 외 | 삭제 → "확인 필요"로 대체 |

### ③ 인용 스니펫 목록화 (정보형만)

3~5개

| # | 스니펫 문장 | 위치 | 유형 |
|---|---|---|---|
| 1 | 예시 문장 | 소제목① | 정의형 |

유형: 정의형("~는 ~이다.") / 수치형 / 실행형 / 경고형

※ 본문 포함 문장만 / 목록화 후 독립 단락 배치 재확인

## STEP 3 — 이미지 프롬프트

들어가며·소제목마다 1개씩 작성.
스타일 순환 (연속 동일 스타일 금지):

### 6-2. 영상 구성 (12~16씬 / 약 50~60초, 1씬 = 1문장)

| 구간 | 씬 수 | 비고 |
|---|---|---|
| 훅 | **1** | hook 타입 1개 고정 — 오프닝 고정 패턴(6-3 규칙 9) 적용 |
| 오프닝 | 1 | hook 다음 첫 scene — 바로 본론으로 (나열식 연결어 자제) |
| 미끼 | 1 | "끝까지 보면 얻는 것" 예고 |
| 핵심 포인트 | 7~11 | 본문 핵심을 씬당 1문장, 전환은 내용으로(연결어 남발 금지) |
| 클라이맥스 | 1 | 가장 중요한 결론·수치 |
| CTA | 1 | 저장·팔로우 유도 |

**★ 비주얼 리듬 — 가장 중요 (이거 안 지키면 밋밋한 영상)**
핵심 포인트 구간을 **전부 `scene`으로 채우지 말 것.** 정보 씬(scene/stat/compare/list)과
**임팩트 씬(`reaction`·`kinetic`)을 교대 배치**해야 영상이 살아난다.

- `reaction` = 이모지 풀스크린 + 그라데이션 (감정·질문·경고 비트). 예) ✅ "3가지 모두 해당하나요?", ⏰ "딱 2주 기회입니다", 🚨 "놓치면 1년 기다려야"
- `kinetic` = 글로우 대형 키워드 + 다크 배경 (수치·키워드 강타). 예) "+6만원", "동시가입 ❌", "이자 비과세"
- **임팩트 씬(reaction+kinetic 합산) = 영상당 4~7개 권장.** 정보 씬 1~2개마다 임팩트 씬 1개 끼우는 리듬.
- 임팩트 씬은 **`"card": false`** (영상전용 — 카드뉴스엔 안 들어감)으로 둔다.
- 같은 임팩트 타입 3연속 금지. reaction↔kinetic↔정보씬을 섞을 것.

### 6-3. 나레이션 작성 원칙 ★가장 중요 (이거 안 지키면 단조로운 영상)

**핵심: 화면(이미지)은 참고자료, 나레이션(`text`)이 주인공이다.**
`text`를 화면 `title`을 그대로 옮긴 설명문으로 쓰면 안 된다. 이미지의 의미만 해치지 않으면
**호기심을 유발하는 자유로운 구어체 대본**으로 새로 쓴다.

작성 규칙:
1. **전체가 하나의 이야기** — 씬을 독립된 정보 나열로 쓰지 말 것. 앞 씬이 다음 씬을
   궁금하게 만드는 흐름(클리프행어): "근데 여기서 함정이…", "문제는 지금부터입니다"
2. **첫 1~2씬에 강한 호기심 후킹** (아래 패턴 중 1개):
   - 정보격차: "이거 모르고 있으면 진짜 큰일 납니다"
   - 손실 회피: "이 돈, 신청 안 하면 그냥 날아갑니다"
   - 사례·스토리: "얼마 전 한 사장님이 이거 몰라서 3천만원 놓쳤습니다"
   - 반전/궁금증: "은행이 거절한 사람만 받을 수 있다는데, 왜일까요?"
   - 질문 던지기: "내가 받을 수 있는지, 30초면 알 수 있습니다"
3. **구어체·짧은 문장·말맛** — 문어체 금지("~합니다만" X). 실제 말하듯이.
4. **어미를 섞어라 ★중요** — 모든 문장을 "~입니다/~습니다"로 끝내면 기계처럼 들린다.
   - 단정: ~입니다 / ~습니다 / ~죠
   - 설명·공감: ~거든요 / ~잖아요 / ~더라고요
   - 부드러움: ~했어요 / ~네요 / ~예요·이에요
   - 질문: ~일까요? / ~아세요?
   - **같은 어미 3연속 금지**, 특히 "~입니다" 반복 금지. 니다체와 요체를 자연스럽게 섞을 것
5. **핵심만** — 숏폼은 한 영상에 메시지 1개. 곁가지 정보는 버리고 후킹→핵심→행동으로.
6. **마지막 CTA**는 놓침 압박 + 저장 유도: "마감 지나면 또 1년 기다려요", "지금 안 챙기면 다음에 못 찾아요" (※ "프로필 링크 확인" 같은 안내성 문구는 쓰지 말 것)
7. **쉼표(,)는 의도적 호흡** — TTS가 쉼표에서 0.18초 쉰다. 강조하고 싶은 단어 앞에 쉼표를 쓸 것
8. **전환은 '내용'으로 — 기계적 연결어 자제 ★v1.1**:
   - "첫 번째로/이어서/그리고/마지막으로" 같은 나열식 연결어를 **매 씬 붙이지 말 것** (번호 매기는 기계 말투).
   - 같은 연결어 **2씬 연속 금지** ("그리고" 다음 또 "그리고" X).
   - 대신 내용으로 이어라: 클리프행어("근데 함정이"), 반문, 호기심("진짜는 따로 있어요").
   - 꼭 필요할 때만 1~2개. hook·cta엔 없음.
8-1. **딱딱한 명사화 어미 금지 ★v1.1**: "~라는 점이에요 / ~기준이고요 / ~인 거예요" 자제 → 입말로 "~막혀요 / ~나왔죠 / ~거든요".
8-2. **소리 내어 읽기 테스트**: 실제로 읽어 어색하면 고치고, 한 호흡에 안 읽히면 자른다.
9. **오프닝 고정 패턴** — hook 씬은 반드시 1개만. `text`는 아래 2가지 중 1가지:
   - 패턴 A: "[대상]이라면 무조건입니다. 서론 없이 첫 번째,"  
     예) "주담대 알아보는 중이라면 무조건입니다. 서론 없이 첫 번째,"
   - 패턴 B: "다음달부터 [변화]인데요. 시간 없으니 바로 첫 번째,"  
     예) "다음달부터 한도가 완전히 바뀌는 건데요. 시간 없으니 바로 첫 번째,"
10. **1인 2역(반문+답)** — 영상당 1회, 중간 scene 씬에서 사용:
    - "[예상 반론]이라고 하실 텐데요, [단호한 답]. 실제로 [근거]거든요."
    - "[불안감]이냐고요? 그럼 오히려 좋습니다. [이유]니까요."
    예) "지방은 유예라서 상관없다고요? 아닙니다. 6월 말이 마감이거든요."

> `title`(화면)과 `text`(나레이션)는 **서로 달라도 된다**. title은 짧은 시각 키워드,
> text는 귀로 듣는 이야기. 예: title "신용 839점 이하" / text "이거 모르면 3천만원 날립니다"

### 6-4. 씬 타입 결정 트리 (위에서부터 first-match — 모호하면 순서가 우선)

```
1. 이모지 하나로 감정·질문·경고를 각인?   → reaction  (이모지 풀스크린 + 그라데이션)
2. 짧은 키워드/수치를 글로우로 강타?       → kinetic   (글로우 대형 키워드, 다크)
3. 순서 있는 절차·단계가 핵심?            → list
4. 두 항목의 '대비/전환'이 메시지?         → compare   (before→after, A보다 B)
5. 단일 수치를 '정보'로 차분히 전달?       → stat      (수치 카드 + 캡션)
6. 그 외 일반 설명                        → scene
훅 씬은 hook, 마지막 씬은 cta 고정
```

- **reaction vs kinetic**: 주인공이 **이모지(감정)**면 reaction, **글자(키워드/수치)**면 kinetic
- **kinetic vs stat**: **임팩트로 강타**하면 kinetic(글로우·다크), **정보로 전달**하면 stat(카드형)
- stat vs compare 타이브레이커: 결론이 **한 값**이면 stat, **둘의 격차**면 compare
- 가드레일:
  - stat·compare 각 **최대 1개** (compare는 좌/우 양쪽 채울 수 있을 때만)
  - reaction+kinetic 합산 **4~7개** (6-2 비주얼 리듬 참고), 같은 타입 3연속 금지
  - reaction/kinetic은 `"card": false` (영상전용)

### 6-5. 필드 규칙

- `text` = **나레이션 = 음성(TTS) + 자막 공용 단일 소스** (모든 씬 필수). 6-3 원칙대로 호기심 후킹 대본
- 화면엔 본문 텍스트가 없다(자막이 나레이션 담당) → 화면 필드는 한눈에 읽히는 짧은 문구로
- 글자수: 훅/CTA `text` 20자 이내 / 내용 씬 30~40자 이내 (자막 2줄 넘기지 않게)
- `"card"`: 생략 시 true(카드뉴스 포함). **reaction/kinetic은 `false`** (영상전용)
- **`"image"` (선택, ★v1.1 비주얼)**: 배경에 깔 **로컬 이미지 절대경로**. 깔리는 타입 = `hook/scene/stat/compare/list`
  (kinetic/reaction/cta는 자체 배경이라 무시). 어두운 오버레이가 자동 입혀져 가독성 유지. 없으면 다크 그라데이션 폴백.
  - 경제 주제는 적합 사진이 드무니 **선택 사항**. 쓰려면 STEP 0.5 출처(국세청·기재부 등) 또는 Wikimedia의
    **license-clear 이미지**를 `이미지수집_v1.1.mjs`(`01_자동화/네이버_블로그/`)로 수집해 그 절대경로를 넣는다.
  - 마땅한 사진이 없으면 비워둔다 → 그라데이션이 오히려 깔끔.

**타입별 화면 필드:**

| 타입 | 화면 필드 (줄바꿈 `\n` 가능) |
|---|---|
| hook / scene | `title` (짧은 시각 키워드) |
| stat | `stat_value` (대형 수치) + `stat_caption` |
| compare | `compare_left.{label,value}` + `compare_right.{label,value}` |
| list | `list_items[]` (절차 항목) |
| **reaction** | `emoji`(1개) + `reaction`(대형 문구) + `sub_text`(보조 1줄) + `gradient` |
| **kinetic** | `keyword`(글로우 키워드) + `keyword_color` + `context`(보조 1줄) |
| cta | `summary[].{label,value,color}` + `cta_button` |

- `gradient` 허용값: `danger`(빨강) / `info`(파랑) / `success`(초록) / `warm`(노랑) / `dark` / `navy`
- `keyword_color` 허용값: `yellow` / `orange` / `red` / `green` / `blue` / `white`
- `title`(화면)과 `text`(나레이션)는 **서로 달라도 된다**. 예) keyword "+6만원" / text "매달 6만원이 그냥 얹혀요"

### 6-7. 실행 (Bash 자동)

scenes.json 저장 후 아래를 순서대로 실행한다. **이전 실행 잔여물 정리 → 검증·렌더 → 캡처 → TTS → 영상**:

> ⚠️ **버전 번호를 하드코딩하지 말 것.** 스크립트는 수시로 새 버전(v2.1→v2.2…)이 생긴다.
> 아래처럼 **항상 가장 높은 버전을 자동 선택**한다 (Walter 버전관리 원칙 = 최고 숫자가 현행).
> 이렇게 해야 스크립트가 올라가도 프롬프트가 낡지 않는다.

```bash
cd "/Users/kakao/Documents/2. 개인/Walter Project/01_자동화/숏폼_자동화"

# ── 최신 버전 자동 선택 (sort -V = 버전 정렬, tail -1 = 최고 버전) ──
SCENE_RENDER=$(ls scene_render_v*.py 2>/dev/null | sort -V | tail -1)
CAPTURE=$(ls capture_v*.mjs        2>/dev/null | sort -V | tail -1)
TTS_RUN=$(ls tts_run_v*.py         2>/dev/null | sort -V | tail -1)
VIDEO_BUILD=$(ls video_build_v*.py 2>/dev/null | sort -V | tail -1)
echo "▶ 사용 버전: $SCENE_RENDER / $CAPTURE / $TTS_RUN / $VIDEO_BUILD"

# ── 폴더 보장 + 잔여물 정리 (output/tts 없으면 타이밍 JSON 저장 실패함) ──
mkdir -p output/scenes output/tts
rm -f output/scenes/*.html output/scenes/*.png output/tts/*.mp3 output/tts/*.json

python3 "$SCENE_RENDER" scenes.json          # JSON 검증 + 씬 HTML (필수 필드 누락 시 중단)
node   "$CAPTURE" output/scenes              # HTML→PNG (로컬 puppeteer, 누락 시 종료)
python3 "$TTS_RUN" scenes.json               # ⚠️ Google Chirp3-HD 여성(유료 ~1센트) → Edge 여성 → gTTS 폴백
BGM=""; [ -f assets/bgm.mp3 ] && BGM="--bgm assets/bgm.mp3"
# ★ --out 으로 STEP 5 카드뉴스와 같은 통합 폴더에 저장 (NNN_YYYYMMDD_키워드는 STEP 5에서 만든 폴더명)
OUTDIR="../../02_콘텐츠/경제/NNN_YYYYMMDD_키워드"
python3 "$VIDEO_BUILD" --scenes-json scenes.json $BGM --out "$OUTDIR"   # 영상 합성 + 자막 정확 동기
```

- **TTS** ⚠️ 1차 엔진 Google Chirp3-HD **여성 보이스**(유료, 영상당 약 1센트). 청크별 실제 길이를 측정해 `scene_XXX_timing.json` 저장 → video_build가 자막 정확 동기에 활용. 키 없거나 실패하면 무료 **Edge 여성→gTTS** 자동 폴백(타이밍 JSON 미생성, 비례 추정)
  - 보이스/속도 바꾸려면: `--voice ko-KR-Chirp3-HD-<이름> --rate <배속>` (기본값은 스크립트 상단 상수)
- **BGM**: 저작권 free 음원(YouTube 오디오 보관함·Pixabay 등)을 `assets/bgm.mp3`로 두면 자동으로 깔림(없으면 BGM 없이 진행)
- `scene_render`가 JSON 필수 필드를 검증 — 실패하면 멈추므로 누락 항목을 고쳐 다시 실행
- `video_build`: timing JSON 있으면 정확 동기, 없으면 비례 추정 폴백. `--scenes-json`으로 기대 씬 수를 검증해 **씬 누락 영상 생성을 차단**. `--no-subtitle`로 자막 비활성화
- **kinetic/reaction 등장 씬은 줌펀치 연출**이 자동 적용된다(파일명에 타입이 들어가 video_build가 감지) → 비주얼 리듬이 영상에서 살아남
