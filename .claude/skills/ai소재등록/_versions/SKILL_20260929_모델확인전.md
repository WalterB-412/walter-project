# AI 소재 등록

작업 폴더: `01_자동화/밀리터리_숏폼/` (실행부 `ai_library_sync_v*.py`)

| 대상 라이브러리 | 용도 | --root |
|---|---|---|
| `01_자동화/밀리터리_숏폼/_library/_ai/` | 밀리터리 숏폼·롱폼 공용 | (기본) |
| `01_자동화/썰_숏폼/_library/_ai/` | 썰 숏폼 | `--root ../썰_숏폼` |

**기본 동작 = 인자 없이 호출되면 두 라이브러리를 연달아 일괄 정리·등록한다.** Walter 요구: "소재등록은 무조건 한번에 진행". 사용자에게 run-id·desc를 묻지 않는다 — 폴더에 떨군 파일을 찾아서 처리하는 게 이 스킬의 일이다.

## 일괄 등록 절차 (기본)

### 0. 동시 세션 확인
`ai_library_sync`는 **`_ai/.index.lock`을 잡지 않는다.** apply 직전에 다른 세션이 같은 라이브러리의 index.json을 쓰는 중이 아닌지 확인한다(최근 수 분 내 index.json mtime 변화, 진행 중인 런). 의심되면 apply만 보류하고 Walter에게 알린다.

### 1. scan — 두 프로젝트 연달아
```bash
cd "/Users/kakao/Documents/2. 개인/Walter Project/01_자동화/밀리터리_숏폼"
SYNC="$(ls ai_library_sync_v*.py|sort -V|tail -1)"
python3 "$SYNC" scan                      # → _work/_ai_review/scan.json + 컨택트시트
python3 "$SYNC" --root ../썰_숏폼 scan    # → ../썰_숏폼/_work/_ai_review/scan.json
```
scan은 index 미등재·파일명 컨벤션 위반(`Boy_opening_lunch_box_20260923123049.mp4` 같은 Flow 원본명)을 잡아 6프레임 컨택트시트를 만든다. 이미 등재된 쌍둥이(md5 동일)가 있는 미등재 사본은 자동 제외된다.

### 2. 눈검수 — 컨택트시트를 Read로 전부 본다
- 파일명(Flow 프롬프트 요약)을 믿지 말고 **화면 기준**으로 이름·키워드를 짓는다.
- 확인할 것: Veo ✦/"Veo" 워터마크(우하단), 타국 마킹(철십자·히노마루 등), 세로/가로, 360p 저해상도, 컷 전환 지점(best_s).
- `reason: dup` 항목은 새 이름을 붙이지 말고 `dedupe`로 기존 등록부터 확인.
- `scene_refs`가 비어있지 않으면 리네임 시 그 씬이 소재를 잃는다 → 이름 유지 또는 보고.
- **런 manifest가 원본 파일명을 경로로 참조 중인지도 확인**(`grep -rl "<원본명>" _work/*/manifest.json`). scan은 scenes.json만 본다. 하드링크(footage/sNN_ai.mp4)는 리네임에 안전하지만 경로 참조는 끊긴다.

### 3. patch.json 작성 (각 프로젝트의 `_work/_ai_review/patch_<날짜>.json`)
```json
[{
  "old_file": "Welder_welding_steel_ship_hull_202609100814.mp4",
  "new_file": "welder-arc-welding-steel-ship-hull.mp4",
  "desc": "welder-arc-welding-steel-ship-hull",
  "keywords": ["용접","조선소","함정건조","불꽃","welder","shipyard","arc-welding","sparks"],
  "note": "AI 연출 화면 · 화면 묘사 한두 줄. 3.3초경 불꽃 최대.",
  "best_s": 3.3,
  "cuts": [{"t": 2.3, "what": "포탑 사격 화염"}]
}]
```
- `new_file`: 소문자-하이픈 영문 2~7토큰, 확장자 유지, 기존 파일과 겹치지 않게.
- `keywords`: **절대 비우지 않는다.** 한국어+영어 혼합(대본은 한국어, 검색어는 영어가 많다).
- `note`: 반드시 "AI 연출 화면"으로 시작. ⚠️ ai_intake `--note`는 고지 자막으로 화면에 구워지므로 intake 경로에서는 "AI 연출 화면"만 넣는다.
- 워터마크·타국 마킹 등 문제 소재는 note에 명시하고 보고.

### 4. apply
```bash
python3 "$SYNC" apply _work/_ai_review/patch_<날짜>.json --dry-run
python3 "$SYNC" apply _work/_ai_review/patch_<날짜>.json
python3 "$SYNC" --root ../썰_숏폼 apply ../썰_숏폼/_work/_ai_review/patch_<날짜>.json --dry-run
python3 "$SYNC" --root ../썰_숏폼 apply ../썰_숏폼/_work/_ai_review/patch_<날짜>.json
```
apply는 index.json 백업(`index.json.bak_<ts>`) → 리네임 → index 갱신(w·h·ar 자동 ffprobe) → usage 키 `ai:{old}`→`ai:{new}` 이관까지 한다.

### 5. 결과 보고
프로젝트별 등록 수, 리네임 목록, 보류(dup·워터마크·마킹·refs) 항목, 세로컷(`ar < 1.0`) 여부.

## 단건 등록 (런 작업 중 특정 씬에 바로 꽂을 때)

```bash
cd "/Users/kakao/Documents/2. 개인/Walter Project/01_자동화/밀리터리_숏폼"
python3 "$(ls ai_intake_v*.py|sort -V|tail -1)" \
  --run-id <run> --scene 3 --file ~/Downloads/veo.mp4 \
  --desc "night-sky-missile-intercept" \
  --keywords 미사일 요격 야간 missile intercept \
  [--note "AI 연출 화면"] [--focus 0.5] [--force]
```
- **intake = 등록이다.** index 등재·md5 중복차단·ar 기록을 intake가 한다. 반입 후 일괄 등록을 다시 돌리지 않는다. 단 `--keywords`(한+영 6개↑)와 `--desc`(재사용 가능한 화면 묘사, 런 번호 금지)를 이 스킬 3단계 기준으로 채운다.
- 반입 배치 뒤 해당 라이브러리만 `scan` 1회 → 0건이면 끝, 남은 건만 일괄 절차 2~4.
- 롱폼: `밀리터리_롱폼/ai_intake_v*.py` (같은 라이브러리).
- 썰: `썰_숏폼/ai_intake_ssul_v*.py`. ⚠️ 미채택 씬엔 안 쓰면서 성공 메시지를 낸다 — manifest `clips`까지 바뀌었는지 직접 확인.
- ⚠️ 사용 중인 씬에 재반입하면 `footage/sNN_ai.mp4`가 교체된다.

## 반드시 지킬 것

1. **keywords를 비우지 마라.** 없으면 `ai_library_find()` 매칭에 영원히 안 걸린다.
2. **같은 영상을 두 번 등록하지 마라.** 같은 md5가 이름 2개가 되면 "동일 소스당 최대 1회" 다양성 규칙이 뚫린다(2026-07-19: 112개 중 70개가 물리적 중복).
3. **같은 desc로 다른 내용을 넣지 마라.** intake는 중단, `--force`로만 덮어쓴다.
4. **세로컷 경고를 무시하지 마라.** 롱폼에 세로 소스가 들어가면 화면 28.5%만 차지(millong_001 사고).

## AI 생성 2트랙 규칙

| 트랙 | 대상 | 생성 방식 |
|---|---|---|
| **A. 무기 특정** | K2 기동, KF-21 이륙, 함정 항주 | 쓸 곳의 비율로 네이티브 생성. 크롭 금지 |
| **B. 개념·범용 B-roll** | 공장, 연구실, 서명하는 손, 태극기, 레이더 그래픽 | 1080p 가로 1회 생성 → 숏폼은 중앙 크롭. 피사체 중앙 1/3 안전존 |

- "전부 가로로 만들어 크롭"은 기각된 안(화소 68% 손실, 군용 피사체가 중앙 31% 밴드에 안 들어옴).
- 가로 → 9:16 크롭 파생본은 md5가 바뀌므로 눈검수 재approve 필수.
