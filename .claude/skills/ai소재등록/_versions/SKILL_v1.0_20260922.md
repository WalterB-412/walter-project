# AI 소재 등록

대상 라이브러리: `01_자동화/밀리터리_숏폼/_library/_ai/` (숏폼·롱폼 공용)
참조: `01_자동화/밀리터리_롱폼/작업스펙_AI컷_비율정합_v*.md`

## 반드시 지킬 것

### 1. `--keywords`를 비우지 마라 ★가장 흔한 사고

keywords가 없으면 `ai_library_find()`의 키워드 매칭에 **영원히 안 걸린다** — 라이브러리에 있는데 못 찾는 상태가 된다. 2026-07-19 정리에서 나온 "빈 keywords" 항목이 전부 이 경로였다.

한국어·영어를 섞어 넣는다(대본은 한국어, 소스 제목은 영어인 경우가 많다).

### 2. md5 중복은 도구가 막지만, 같은 영상을 두 번 등록하지 마라

런 중 한 번 등록하고 나중에 `_ai` 폴더에 직접 드롭해 또 등록하면 **같은 md5가 이름 2개**가 된다. 그러면 "동일 소스 영상당 최대 1회" 다양성 규칙이 뚫린다. 2026-07-19 실측: _ai 112개 중 70개(34그룹)가 물리적 중복이었다.

v1.1+는 md5로 먼저 조회해 기존 항목을 재사용하지만, **manifest의 source_id가 기존 desc로 맞춰지는지** 확인한다(사용 대장의 신원 일치가 핵심).

### 3. 같은 `--desc`로 다른 내용을 넣지 마라

이름은 같은데 내용이 다르면 도구가 **중단**한다. `--force`로만 덮어쓴다. 예전에는 파일은 옛것이 남고 index에만 새 항목이 붙어 _library와 런이 다른 영상을 갖는 **조용한 분기**가 생겼다.

### 4. 세로컷 경고를 무시하지 마라

세로(`ar < 1.0`)로 반입하면 "롱폼에서는 못 쓴다"고 그 자리에서 알린다. 롱폼 빌드에 세로 소스를 넣으면 **폭 547px = 화면 28.5%**만 차지하고 나머지 71.5%가 블러 액자가 된다(millong_001 s24·s49·s50·s53 사고).

index에는 `w`·`h`·`ar`(소수 3자리)가 기록되며, 반입 시 자동으로 들어간다.

## 라이브러리 관리

```bash
# 인덱스 동기화 (디스크 ↔ index.json)
python3 "$(ls ai_library_sync_v*.py|sort -V|tail -1)" --dry-run
# 비율 필드 백필 (기존 항목 ffprobe)
python3 "$(ls ai_ratio_backfill_v*.py|sort -V|tail -1)" --report
# 워터마크 제거
python3 ai_unmark_v1.0.py <in.mp4> <out.mp4> <t_ref> "x0,y0,x1,y1;..." [debug.png]
```

⚠️ **동시 세션 주의.** `_ai/index.json`은 `fcntl.flock` 트랜잭션으로 보호되지만, **락을 안 잡는 구버전 도구와 동시에 돌리면 여전히 유실된다.** 백필·동기화는 다른 Claude 세션이 이 라이브러리를 쓰고 있지 않은지 확인한 뒤 실행한다.
