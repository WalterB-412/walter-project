# 네이버 테크 블로그 포스팅 프롬프트 v1.0
IT · AI · 전자기기 전용 / SEO · AEO · GEO 통합형
(경제 블로그 v6.17 기반 파생 — 검증된 메커니즘 유지, 도메인 규칙만 교체)

## 사용 방법

1. 사용자가 입력한 [주제]로 작업한다.
2. STEP 0부터 순서대로 진행한다.
3. 단계 순서 변경·생략·병합 금지.
4. 글은 마크다운 파일로 작성 금지.
5. 최종 출력: 네이버 블로그 바로 붙여넣기 형태.
6. STEP 4 완료 후 STEP 5(카드뉴스)를 자동으로 이어서 진행한다. 별도 명령 없이 실행.
7. STEP 5 완료 후 STEP 6(숏폼 영상)을 자동으로 이어서 진행한다. 별도 명령 없이 실행.

## 시작 전 필수 판별

### ① 콘텐츠 타입 (최우선) — 질의 유형·AEO 가동을 결정

| 타입 | 설명 | 질의 유형 | AEO·GEO |
|---|---|---|---|
| **리뷰형** | 스마트폰·노트북·이어폰 등 직접 사용기 | 비정보형(상업·비교) | 생략, SEO 집중 |
| **가이드형** | Claude·ChatGPT·Gemini 등 AI 도구 활용법 | 정보형(방법) | **풀가동** (인용 스니펫 3개) |
| **뉴스형** | 출시 발표·펌웨어 업데이트·스펙 정리 | 정보형(혼합) | 부분 적용 (정의·수치 문장만) |

> ⚠️ 한 포스팅엔 1타입만. 혼용 금지.

### ② 핵심 독자 (1그룹만 타겟 — 혼용 금지)

| 그룹 | 연령대 | 특성 |
|---|---|---|
| 구매고려자 | 30~50대 | 비전문가, 가성비·추천 명쾌함 선호 |
| 얼리어답터 | 20~40대 | 스펙 수치 이해 가능, 벤치마크 관심 |
| 직장인·실용사용자 | 전 연령 | AI 도구 업무 효율화 목적 |

### ③ 주력 후킹 감정
**정보 격차 · 실용** → "대부분이 모르는 숨겨진 기능", "이렇게 쓰면 10배 빨라진다"
- 경제판의 "손실·피해 방지"와 달리 **발견의 기쁨·우월감** 자극

### ④ AEO 인용 후보 문장 3개 사전 설계 (가이드형·뉴스형만)
- 형식: "[용어·기능]은 [정의]다." (20자 이내, 정의문만 허용)
- 예) "Claude 프로젝트는 파일을 영구 저장하는 작업 공간이다."
- 소제목 결론 문장과 동일 문장 사용 금지
- 독립 단락 배치 (앞뒤 줄바꿈 + 문장 직후 엔터)
- ※ 리뷰형은 이 단계 생략

## 형식 앵커

각 섹션 작성 시 아래 형식을 기준으로 삼는다.

| 섹션 | 형식 |
|---|---|
| 정답 박스 | [단정형 결론 20자↓] · [수치 포함 결론] · [조건형 결론] + ▶ 실행/체크 3단계 (동사 시작) |
| 들어가며 | [독자 상황] → [문제·궁금증] → [결과 약속] + 말미: "이 글을 정리한 이유는 ~이다." |
| 중간 요약 | ① 소제목명: 결론 1줄 압축 (소제목 원문 그대로 복사 금지) |
| FAQ | Q. [본문 미포함 질문] / A. 단정형 2~3줄 × 5개 |
| 요약 표 | 항목 \| 수치·조건·기준 (문장형 설명 금지) |

※ 같은 문장 2곳 이상 → 즉시 삭제
※ 같은 수치 3곳 이상 → 최초 1곳만 유지

## STEP 0 — 웹검색 사전 수집

① 핵심 스펙·수치 + 공식 출처 (제조사 spec 페이지·뉴스룸)
② 출시일·지원 종료일·모델명·버전·호환 조건
③ 신뢰 미디어 측정값 (The Verge · GSMArena · NotebookCheck)
④ 네이버 자동완성 키워드 5개
⑤ 연관검색어 5개
⑥ 검색 의도: 리뷰형 / 가이드형 / 뉴스형 중 선택 (①번 판별과 일치)
⑦ 발행 주기 확인: 최근 발행일, 주 2~3회 간격 권장 / 시리즈 연결 가능 여부 → 가능하면 STEP 3.5 활용

⑧ 실제 후기·체험 소재 수집
검색 쿼리:
- 제품: "[제품명] 실사용/단점/비교/후기" → 클리앙·뽐뿌 우선
- AI 도구: "[도구명] 안됨/오류/대비/한계" → X(트위터)·Reddit 병행

수집 목표:
- 막힘 사례: 공식 스펙엔 없는 실제 문제 → "[상황] → [발생 문제]"
- 반전 사례: 기대와 달랐던 결과 → "[예상 스펙] vs [실제 체감]"
- 수치 사례: 실제 배터리·성능·속도 → "[조건] → [측정값]"

※ 커뮤니티 측정값은 STEP 0.5 팩트 테이블 등재 불가 → 본문 인용 시 "커뮤니티 측정 기준" 명시
※ 검색 결과 없으면 "(예상 시나리오)" 표기 후 진행

## STEP 0.5 — 팩트 테이블 구축

STEP 0 완료 직후 실행. **STEP 1 진행 전 반드시 완료.**

### ① 검증 필요 항목 추출

STEP 0 수집 내용에서 아래 유형을 분리 추출:
- 스펙 수치: 칩셋·RAM·저장용량·화면·배터리
- 날짜: 출시일·지원 종료일·업데이트 배포일
- 모델명·버전: 정확한 모델 번호, AI 모델 버전
- 호환·적용 조건: 지원 기기·OS·플랜 요건

### ② 항목별 출처 확인 — 검색 우선순위

```
1순위: 제조사 공식 spec 페이지 (WebFetch)
2순위: 공식 뉴스룸·프레스 릴리즈
3순위: The Verge · GSMArena · NotebookCheck
4순위: 커뮤니티 측정값 (팩트 테이블 등재 불가, 본문서 별도 표기)
```

### ③ 팩트 테이블 완성 (STEP 1 진행 전 필수 출력)

| 항목 | 수치·내용 | 출처 | 확인 상태 |
|---|---|---|---|
| 예) 갤럭시S26 칩셋 | Snapdragon 8 Gen5 | samsung.com/.../spec | ✅ |
| 예) 배터리 지속시간 | 18시간 (영상재생) | notebookcheck.net | ⚠️ |
| 예) 출고가 | 1,155,000원 | 2026.6 기준 | ⚠️ |
| 예) 게임 평균 FPS | 미확인 | 검색 결과 없음 | ❓ |

**확인 상태 기준 (테크용 — 경제판과 다름):**
- ✅ **제조사 공식 스펙**: 공식 spec 페이지·뉴스룸 직접 확인
- ⚠️ **리뷰 미디어 측정값**: 테스트 유닛·환경 편차 존재 → 본문에 `([매체명] 측정 기준)` 병기
- ❓ **확인 필요**: 검색 결과 없음 또는 커뮤니티 체감 → 수치 단정 금지

### ④ 가격 전용 규칙 (테크 필수)

- **가격은 절대 ✅로 분류 금지.** 출시가/할인가가 수시 변동 → 항상 ⚠️.
- 가격 기재 시 반드시 날짜 병기: "1,155,000원 (2026년 6월 기준)"
- card-03·숏폼 클라이맥스에서 가격을 hero 수치로 쓸 때도 날짜 스탬프 필수.

### ⑤ 팩트 테이블 사용 규칙 — STEP 1 전 구간 적용

- ✅ 항목: 수치 그대로 사용 가능
- ⚠️ 항목: 사용 가능, 문장 말미 `([매체명] 측정 기준)` 또는 `(YYYY년 M월 기준)` 병기
- ❓ 항목: 수치 직접 기재 금지 → "확인 필요" 또는 서술형 대체
- **팩트 테이블에 없는 스펙·날짜·모델명 인라인 기재 금지**

## STEP 1 — 포스팅 본문 작성

### 문체·형식
- 존댓말 금지 / ~한다·~이다 형식
- 본문 3,000자 이내 / 억지 분량 늘리기 금지
- 스펙·날짜·출처 병기: 예) "18시간 지속 (NotebookCheck 측정 기준)"
- 스펙 단위 표기: 처리속도 GHz / 저장 GB·TB / 밝기 nit / 주사율 Hz / 배터리 mAh·Wh / 무게 g / 두께 mm / AI 응답속도 token/s
- AI 모델·OS 버전은 반드시 "~기준 (2026년 M월)" 병기
- 말미 면책 고지 필수

### 줄바꿈 규칙 — 전 구간 예외 없음
- 1줄 = 공백 포함 23자 이내, 초과 시 즉시 엔터
- 1문단 = 2~4문장 / 소제목: ① ② ③ 번호 삽입

### GEO 파싱 신호 — 가이드형·뉴스형만 적용 (리뷰형 생략)
① 소제목 직후 첫 문장 → 결론형 필수: "~는 ~이다." / "~하면 ~된다."
② 소제목 1개 이상 → 질문형 필수: "~는 어떻게 하나?" / "~은 무엇인가?"
③ 숫자·조건·기준 → 문단 첫 줄 배치 (중간 삽입 금지)
④ 각 소제목 → 타 소제목 참조 없이 단독 완결 구조

### 전략 박스 (타입별 — 정답 박스 자리)

```
리뷰형   → [한줄 결론] + [추천 대상 2줄] + [비추천 대상 1줄]
            + ▶ 구매 전 체크 3가지 (동사 시작)
가이드형 → [이 도구는 ~인 데 가장 효과적이다]
            + ▶ 활용 3단계 (동사 시작)
뉴스형   → [핵심 변경사항 1줄] + [기존 대비 달라진 점]
            + ▶ 지금 해야 할 행동
```

### 제목 3안 (타입별)

```
리뷰형  "[제품명] 직접 써봤더니 + 솔직 평가"
        "[A] vs [B] → 실제로 뭐가 나은가"
뉴스형  "[제품·AI도구명] 업데이트 정리 2026"
        "[연도] + [핵심 키워드] + [정량 결과]"
가이드형 "[도구명] 이 기능 모르면 반만 쓰는 겁니다"
        "[작업]을 10배 빠르게 하는 [도구명] 활용법"
```
※ 리뷰형·비교형 중 1개 이상: "직접/써봤더니/솔직" 포함 필수

### 신뢰 장치 — 필수 9종

경제판 5종 유지:
- 조건 명시: "~의 경우에만 해당한다."
- 주의사항: "~라고 오해하기 쉽지만, 실제로는 ~이다."
- 과장 제거: "무조건" → "가능성이 높다" / "누구나" → "대부분"
- 팩트 테이블 준수: ✅·⚠️ 항목만 수치 사용 / ❓ 항목 수치 불가
- 검증 상태 표기: ⚠️ 항목에 `([매체명] 측정 기준)` 병기

테크 추가 4종:
- 스펙 출처 명시: "제조사 공식 기준"
- 가격 면책: "가격은 시점에 따라 변동될 수 있다"
- 협찬 여부: 협찬 시 포스팅 **상단 첫 줄 + 하단** 양쪽 표기 (공정위 추천·보증 심사지침)
  - "본 글은 [브랜드]로부터 제품을 제공받아 작성되었습니다"
  - 제휴 링크(쿠팡파트너스 등) 사용 시: 링크 옆 "(파트너스 링크, 수수료를 받습니다)" 표기
- 버전·날짜 명시: AI 도구는 반드시 "~기준 (2026년 M월)" 병기

### 표 vs 텍스트
- 표 사용: 스펙 비교 / 가격대별 추천 / A vs B / 기능 가능·불가능 정리
- 줄글 사용: 개념·흐름 / 주의사항·예외·팁 / 활용 가이드 / 마무리 체크리스트

### 소제목별 단락 구조 — 5단계 의무

**1단계.** **결론 (3줄 이내, 굵게)** ← GEO: 첫 문장 결론형 (가이드형·뉴스형)
**2단계.** 이유·근거 (출처 병기)
**3단계.** 막힘·실수담 ← STEP 0 ⑧ 수집 소재 우선
  - 형식: "스펙엔 ~라고 나오지만, 실제로 써보니 ~이었다."
  - 소재 없으면 커뮤니티 사례 또는 "(예상 시나리오)" 대체
**4단계.** 수치 비교 또는 Before/After
**5단계.** ※ 주의사항·예외 (지원 조건·호환성 등)

사례 우선순위: ① 직접 체험 ② 측정값 비교 ③ 미디어 인용 ④ B/A 비교 ⑤ 가상 시나리오 (최후 수단, 전체 최대 2회)

### 포스팅 필수 항목 — 순서 준수

1. 제목 3안 (위 타입별)
2. 메타설명: 핵심결론 + 수치 + 독자혜택, 100~150자
2-1. 카테고리 태그: [대분류] [중분류] [세부주제] (해시태그 혼용 금지)
3. 용어 해설 표: 5~7개 / "[용어]는 [정의]다." 형식 / 각 정의문 독립 단락
4. 목차: [이 글에서 다루는 내용] ✔ 형식
5. 전략 박스 (타입별)
6. 들어가며 (형식 앵커)
7. 소제목별 본문: 5단계 구조 + 중간 질문 1개 + 강조 문장 2개
7-1. 중간 저장 유도 (소제목 ②~③ 사이, 1회만):
   - "이 글 마지막에 모델별 스펙 비교 표를 정리해뒀다."
   - "마지막에 잘못 쓰기 쉬운 3가지와 해결법을 정리했다."
8. 중간 요약 (형식 앵커)
9. FAQ 5개 (본문 미포함 질문)
10. 최종 요약 표
11. 마무리
   - 독자 질문 유도 (마무리 직전, 1회): "직접 써보니 [구체적 경험] 어떠셨나요?"

- 임팩트 씬은 `"card": false` (영상전용). 같은 타입 3연속 금지.

### 6-3. 나레이션 작성 원칙 ★가장 중요

**핵심: 화면(이미지)은 참고자료, 나레이션(`text`)이 주인공이다.**

1. **전체가 하나의 이야기** — 클리프행어: "근데 여기서 진짜는…", "문제는 지금부터입니다"
2. **첫 1~2씬 강한 후킹** (정보격차 중심):
   - 정보격차: "이거 모르면 반만 쓰는 겁니다"
   - 발견: "공식 설명에도 안 나오는 방법이에요"
   - 반전: "비싸 보여도 사실 이게 제일 가성비예요"
   - 질문: "지금 쓰는 그 방법, 사실 제일 느린 거 아세요?"
3. **구어체·짧은 문장·말맛** — 문어체 금지.
4. **어미를 섞어라 ★** — "~입니다" 반복 금지. 니다체+요체 자연스럽게 섞기.
   - 단정: ~입니다/~죠 / 공감: ~거든요/~잖아요/~더라고요 / 부드러움: ~했어요/~네요 / 질문: ~일까요?/~아세요?
   - 같은 어미 3연속 금지.
5. **핵심만** — 한 영상 메시지 1개. 후킹→핵심→행동.
6. **마지막 CTA**는 정보격차 압박 + 저장: "저장 안 하면 다음에 못 찾아요", "이미 아는 사람은 지금 세팅하고 있어요" (※ "프로필 링크 확인" 금지)
7. **쉼표(,)는 의도적 호흡** — TTS가 0.18초 쉼. 강조 단어 앞에 쉼표.
8. **전환은 '내용'으로 — 기계적 연결어 자제 ★v1.1**:
   - "첫 번째로/이어서/그리고/마지막으로" 같은 나열식 연결어를 **매 씬 붙이지 말 것** (번호 매기는 기계 말투).
   - 같은 연결어 **2씬 연속 금지** ("그리고" 다음 또 "그리고" X).
   - 대신 내용으로 이어라: 클리프행어("근데 함정이"), 반문, 호기심("진짜는 따로 있어요").
   - 꼭 필요할 때만 1~2개. hook·cta엔 없음.
8-1. **딱딱한 명사화 어미 금지 ★v1.1**: "~라는 점이에요 / ~기준이고요 / ~인 거예요" 자제 → 입말로 "~막혀요 / ~나왔죠 / ~거든요".
8-2. **소리 내어 읽기 테스트**: 실제로 읽어 어색하면 고치고, 한 호흡에 안 읽히면 자른다.
9. **오프닝 고정 패턴** — hook 씬 1개만. `text`는 둘 중 1:
   - 패턴 A: "[제품·도구] 쓰는 분이라면 무조건입니다. 서론 없이 첫 번째,"
   - 패턴 B: "[기능·업데이트] 나왔는데요, 아는 사람만 압니다. 바로 첫 번째,"
10. **1인 2역(반문+답)** — 영상당 1회, 중간 scene 씬:
    - "[예상 반론]이라고 하실 텐데요, [단호한 답]. 실제로 [근거]거든요."
    예) "ChatGPT가 더 낫지 않냐고요? 이 기능은 Claude만 됩니다."
    예) "구형 모델이면 안 된다고요? 설정 하나면 됩니다."

> `title`(화면)과 `text`(나레이션)는 서로 달라도 된다. title은 짧은 시각 키워드, text는 귀로 듣는 이야기.

### 6-4. 씬 타입 결정 트리 (위에서부터 first-match)
```
1. 이모지 하나로 감정·질문·강조를 각인?   → reaction
2. 짧은 키워드/수치를 글로우로 강타?       → kinetic
3. 순서 있는 절차·단계가 핵심?            → list
4. 두 항목의 '대비/전환'이 메시지?         → compare
5. 단일 수치를 '정보'로 차분히 전달?       → stat
6. 그 외 일반 설명                        → scene
훅 씬은 hook, 마지막 씬은 cta 고정
```
- reaction vs kinetic: 주인공이 이모지면 reaction, 글자(키워드/수치)면 kinetic
- kinetic vs stat: 임팩트 강타=kinetic(글로우·다크), 정보 전달=stat(카드형)
- stat vs compare: 결론이 한 값이면 stat, 둘의 격차면 compare
- 가드레일: stat·compare 각 최대 1개 / reaction+kinetic 합산 4~7개, 같은 타입 3연속 금지 / reaction·kinetic은 `"card": false`

### 6-5. 필드 규칙
- `text` = 나레이션 = 음성(TTS)+자막 공용 단일 소스 (모든 씬 필수)
- 화면 필드는 한눈에 읽히는 짧은 문구로
- 글자수: 훅/CTA `text` 20자 이내 / 내용 씬 30~40자 이내
- `"card"`: 생략 시 true. reaction/kinetic은 false
- **`"image"` (선택, ★v1.1 비주얼)**: 배경에 깔 **로컬 이미지 경로**. 깔리는 타입 = `hook/scene/stat/compare/list`
  (kinetic/reaction/cta는 자체 배경이라 무시). 어두운 오버레이가 자동으로 입혀져 텍스트 가독성 유지.
  → STEP 3-D에서 수집한 공식 사진(`02_콘텐츠/블로그테크_이미지/...`)이나 본인 촬영분의 **절대 경로**를 넣는다.
  - 정보 씬에 사진을 깔면 밋밋함이 사라진다. 제품 외형 씬일수록 효과 큼.

| 타입 | 화면 필드 (`\n` 가능) |
|---|---|
| hook / scene | `title` |
| stat | `stat_value` + `stat_caption` |
| compare | `compare_left.{label,value}` + `compare_right.{label,value}` |
| list | `list_items[]` |
| reaction | `emoji` + `reaction` + `sub_text` + `gradient` |
| kinetic | `keyword` + `keyword_color` + `context` |
| cta | `summary[].{label,value,color}` + `cta_button` |

- `gradient`: danger / info / success / warm / dark / navy
- `keyword_color`: yellow / orange / red / green / blue / white

```bash
cd "/Users/kakao/Documents/2. 개인/Walter Project/01_자동화/숏폼_자동화"
```
