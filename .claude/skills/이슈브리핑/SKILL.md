## 절차

### 1. 히스토리 로드 — 중복부터 막는다

```bash
cat "/Users/kakao/Documents/2. 개인/Walter Project/01_자동화/이슈_히스토리.json"
```
`{"date", "category", "title"}` 배열이다. **이미 다룬 주제는 후보에서 제외**한다. 같은 사안이라도 **새 국면이 생겼으면 후보로 살린다**(예: 신청 개시 → 지급일 확정). 그때는 무엇이 새로운지 명시한다.

### 2. 카테고리별 이슈 수집 [웹검색]

각 카테고리마다 **최근 2주 내** 이슈를 웹검색으로 찾는다. 카테고리당 2건 내외.

수집 기준:
- **날짜가 박힌 변화** — 시행일·신청 마감·지급일·인상률
- **독자가 돈으로 체감**하는 것 — 얼마를 더 받거나 덜 내나
- **행동 가능** — 신청하거나 갈아타거나 대비할 수 있나

버릴 것: 전망·논평만 있는 기사, 이미 지나간 마감, 특정 상품 홍보성 기사.

### 3. 브리핑 출력

```
📋 경제 이슈 브리핑 — YYYY-MM-DD

[정부지원금·보조금]
1. <제목> — <한 줄 요약> (출처: <매체>, <날짜>)
2. ...

[연금·노후]
...
```

사실 기반 내용은 **출처를 달거나 "확인 필요"로 표시**한다.

### 4. 추천 TOP 3

검색량·시의성·경쟁도·수익 관련성을 종합해 3개를 고르고, 고른 이유를 한 줄씩 적는다.

### 5. 🥊 악마의 변호인 검증 ★필수

**TOP 3를 그대로 확정하지 않는다.** 각 후보를 스스로 공격한 뒤 살아남은 것만 통과시킨다. 목적은 **헛글 방지** — 쓰나 마나 한 글에 시간을 쓰지 않는 것.

각 후보마다 세 가지를 따진다:

| # | 질문 | 확인할 것 |
|---|---|---|
| ① | **안 먹힐 이유는?** | 검색 수요가 실제로 있나. 독자가 이걸 검색할 이유가 있나. 너무 일반적이라 클릭할 동기가 없지 않나 |
| ② | **경쟁 포화도는?** | 이미 상위 노출 글이 몇 개나 되나. 대형 매체·공식 블로그가 선점했나. 내가 더 나은 걸 쓸 여지가 있나 |
| ③ | **더 나은 앵글은?** | 같은 소재를 다르게 자를 수 없나. 대상을 좁히거나(예: 전체 → 자영업자) 시점을 바꾸면(예: 제도 소개 → 놓치면 손해) 살아나지 않나 |

출력 형식:
```
🥊 악마의 변호인

후보 1: <제목>
 ① 안 먹힐 이유 — ...
 ② 경쟁 포화도 — ...
 ③ 더 나은 앵글 — ...
 → 판정: 통과 / 앵글 수정 후 통과 / 탈락
```

**세 후보가 다 탈락해도 억지로 살리지 않는다.** 그때는 2단계로 돌아가 다른 카테고리에서 다시 고른다.

### 6. 최종 확정

통과분만 남겨 최종 주제를 제시한다. 앵글이 수정됐으면 **수정된 앵글로** 적는다.

### 7. 히스토리 append

확정 주제를 `이슈_히스토리.json`에 추가한다.
```json
{"date": "YYYY-MM-DD", "category": "<카테고리>", "title": "<제목>"}
```
**기존 항목을 지우거나 고치지 않는다.** 배열 끝에 덧붙이기만 한다.

### 8. 다음 단계 안내

확정된 주제로 `blog` 스킬을 이어서 돌릴지 묻는다.
